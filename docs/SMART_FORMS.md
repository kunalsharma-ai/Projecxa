# Smart forms

Milestone 32. Components live in `apps/web/components/form/`, and the rules are in `apps/web/lib/form-rules.ts`. You can try every control at **Form gallery** (`/settings/forms`), which saves nothing.

## Controls

Each control works on its own or inside `FormField`. `FormField` provides the label, required marker, help tip, hint and error. The error is tied to the control with `aria-describedby` and announced with `role="alert"`.

| Control | File | Keyboard |
| --- | --- | --- |
| `FormField`: persistent or floating label, `HelpTip` (contextual tooltip) | `field.tsx` | Tab to the "?" to read the tip; Escape closes it |
| `Combobox`: searchable select, or multi-select with chips (`multiple`). Supports server search (`onSearch`, auto-complete), groups, `creatable` and `max` | `combobox.tsx` | Type to filter. ↑/↓ moves, Home/End jump to the first/last option, Enter picks, Escape closes. Backspace in an empty search removes the last chip |
| `CountrySelect` (flags, one or many) and `CurrencySelect` (common currencies first; search by code, name or country) | `combobox.tsx` | As Combobox |
| `DatePicker`: understands typed dates such as `today`, `tomorrow`, `+7`, `+2w`, `30/11/2026` or `5 Jan 2027`, and has a calendar | `date.tsx` | In the calendar, arrows move by day or week, PageUp/PageDown by month and Home/End to the start or end of the week. Enter picks; Escape closes |
| `DateRangePicker`: presets plus a two-click calendar with a hover preview | `date.tsx` | As the calendar |
| `RadioCards`, `CheckboxGroup` (with "Select all"), `Segmented`, `Switch` | `choice.tsx` | In radio groups and segmented controls, the arrow keys move and select |
| `TagInput`: adds tags on Enter or comma, splits a pasted list, checks each tag, offers suggested tags | `tags.tsx` | Enter or comma adds a tag. Backspace in an empty box removes the last tag |
| `InlineEdit`: click-to-edit text that saves when you leave the field, with saving and saved states and inline errors | `tags.tsx` | Enter saves (Ctrl+Enter when it has several lines). Escape cancels |
| `RichText`: light Markdown (bold, italic, heading, lists, links) with a toolbar and Preview. `RichTextView` renders it as React elements, never as HTML | `rich-text.tsx` | Ctrl+B for bold, Ctrl+I for italic, Ctrl+K for a link |
| `FileDrop`: drag-and-drop or browse, checks file type and size, shows a file list with remove buttons | `rich-text.tsx` | Enter or Space opens the file picker |

Controls follow the active theme and its density (`--field-y`). There are no colours written into the code.

## SmartForm (schema-driven)

`<SmartForm schema={…} onSubmit={…} />` draws the whole form from a schema. A schema is a list of **sections**. Each section has an optional title and description, a column count (1–4) and an optional `showIf`. Each **field** has the settings below.

**What the field is:**
- `name`, `type`, `label`, `hint`, `help` and `placeholder`.
- `type` is one of: text, email, url, number, textarea, richtext, select, multiselect, country, countries, currency, date, daterange, radiocards, checkboxes, segmented, switch, tags, file, or group.
- `group` makes a repeatable set of fields, controlled by `fields`, `minItems`, `maxItems` and `itemLabel`.

**Rules:**
- `required` can be `true` or a function of the form's values.
- Limits: `min`, `max`, `integer`, `minLength`, `maxLength`, and `pattern` (a regular expression with a message).
- `validate(value, values)` adds any other check.
- `showIf(values)` hides the field. Hidden fields and sections are not validated and not submitted.

**Layout:**
- `span` sets how many columns the field takes: 1, 2, 3 or `full`. Wide controls are full width by default.
- `floating` gives short text fields a floating label.
- `props` passes settings to the control, such as `columns`, `selectAll`, `accept`, `maxSizeMb`, `prefix`, `suffix`, `suggestions`, `validateTag` and `normalise`.

**Suggestions:** `suggest(values)` returns `{ value, label?, reason? }`. The form shows it under the field with **Use** and dismiss buttons.

The form also handles:
- **Validation:** a field is checked when you leave it, and the whole form is checked on submit. An error summary at the top links to each field. Nested fields are labelled like "Contact 2 › Email".
- **Submitted values:** only visible fields are sent. Text is trimmed and numbers are converted.
- **Drafts:** with `draftKey`, unsent values are kept in this browser and offered back next time, with a **Discard it** option. Files are never stored.
- **Unsaved changes:** the browser warns before you leave a page with a changed form.
- **Keyboard:** Ctrl+Enter (⌘+Enter on Mac) submits from anywhere in the form.
- **Density:** `density="compact"` or `"comfortable"` overrides the theme's density for one form.

## Suggestions are rule-based

The suggestions are not generated by an AI model. They come from simple rules in `lib/suggest.ts`, run in the browser, so nothing is sent anywhere:

- **Client or vendor code from the name.** It takes initials and skips words like Ltd, GmbH and Inc. If the code is taken, it adds a number (for example `AI3`).
- **Vendor redirect domain from the callback URL's host.**
- **Website domain from a work email.** Free mail providers are ignored.
- **Quote currency from the first market** (in the gallery).

A field's `suggest` function can call the server instead, for example the AI copilot.

## Where it is used

- **Clients → Add client:**
  - name
  - code: checked for format and uniqueness, with a suggested code
  - contacts: repeatable, each with name, email and phone
  - billing address and tax ID
  - the draft is kept
- **Clients → Billing details:** inline edit; each field saves on its own.
- **Vendors → Add vendor:**
  - name
  - code: with a suggested code
  - callback URL template: checked as a URL
  - redirect domains: as tags, each checked and normalised, with the callback's host suggested
- **Form gallery:** a demo study brief that uses every control, with a compact/comfortable switch and live values.

Other forms will move to SmartForm when they are next changed.

## Tests

`pnpm --filter @projexa/web test` runs `scripts/check-forms.ts` (it is part of CI). It covers:
- every validation rule
- `showIf` and group paths
- the submitted values
- typed dates
- the suggestion rules
